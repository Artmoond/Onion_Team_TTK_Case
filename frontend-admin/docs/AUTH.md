# Авторизация организатора

Админка показывает формы входа и регистрации до открытия редактора. Состояние
сессии проверяется при каждой загрузке приложения через backend. Ответ с
`401` показывает форму входа; сетевые ошибки и отсутствие auth endpoint
показывают уведомление, а редактор остаётся закрытым.

## API-контракт для backend

Все endpoints используют JSON и доступны под `VITE_API_URL`.

| Метод и путь | Тело запроса | Успешный ответ |
| --- | --- | --- |
| `GET /api/auth/me` | — | `200 { "user": { "id", "email", "name" } }`; `401`, если сессии нет |
| `POST /api/auth/register` | `{ "name", "email", "password" }` | `201` или `204`; после регистрации пользователь входит отдельно |
| `POST /api/auth/login` | `{ "email", "password" }` | `200 { "user": { "id", "email", "name" } }` и установка cookie сессии |
| `POST /api/auth/logout` | — | `204` и удаление cookie сессии |

Ошибки рекомендуется возвращать как `{ "detail": "Понятное сообщение" }` с
подходящим HTTP статусом (`400`, `401`, `409`, `422`). Клиент выводит сообщение
в общем toast-компоненте. Ответ `401` на `GET /api/auth/me` означает обычное
отсутствие активной сессии.

## Требования безопасности

- Backend принимает пароль по HTTPS, хэширует его при регистрации алгоритмом
  для хранения паролей (например, Argon2id с уникальной солью) и сравнивает
  пароль только через штатную функцию проверки хэша. Не хранить пароль или его
  быстрый SHA-256 digest.
- Клиентская отправка хэша вместо пароля сама по себе не защищает аккаунт:
  такой хэш становится повторно используемым секретом. В текущем контракте
  пароль передаётся только auth endpoint по TLS; браузер не сохраняет его.
- Сессия передаётся в cookie с `HttpOnly`, `Secure` в production,
  `SameSite=Lax` или более строгим режимом, разумным сроком жизни и ротацией.
  Auth endpoints должны иметь защиту от CSRF согласно выбранной cookie/CORS
  схеме и ограничение частоты попыток входа.
- При CORS backend должен разрешить конкретный origin админки и credentials;
  wildcard origin вместе с credentials использовать нельзя.
- Не включать пароль в логи или тексты ошибок. Не сохранять пароль и session ID
  в `localStorage`, `sessionStorage` или черновиках редактора.

Пока backend не готов, успешная авторизация не эмулируется локально. Это
предотвращает открытие редактора без реальной серверной проверки.
