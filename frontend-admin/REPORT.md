# Отчёт: редактор интерактивных карт павильонов

Дата: 2026-10-24  
Ветка: `youngire-frontend-admin`  
Зона изменений: только `frontend-admin/`

## 1. Задача

Сделать полноценный frontend-редактор для организатора выставки:

- загрузка плана павильона и расстановка точек интереса (POI);
- разметка стен, помещений и масштаба;
- привязка 360° панорам к точкам;
- сохранение и публикация данных без ручной работы с JSON-файлами;
- публикация на существующий backend и QR-код публичной ссылки.

Дополнительные требования: не менять `shared/types.ts` и `shared/mock_venue.json`,
не добавлять новые endpoint, работать на порту `3001`, сохранять совместимость
с `frontend-client` и `backend`.

## 2. Что изучено перед реализацией

- `shared/types.ts`: базовая модель `Venue → Floor → POI/Panorama/NavGraph`.
- `shared/mock_venue.json`: эталонная демо-площадка, slug `ttk-expo`.
- `backend/app/main.py`: реальные endpoint:
  - `GET /api/health`
  - `GET /api/venues`
  - `GET /api/public/{slug}`
  - `PUT /api/venues/{slug}`
  - `POST /api/upload` → `{ url, size }`
  - статика `/uploads/*`
- `backend`: in-memory хранилище, загрузки в `data/uploads`, MVP-маршрут только
  по первому этажу, авторизации нет.
- `docker-compose.yml`: порт `3001`, `VITE_API_URL=http://localhost:8000`.
- `frontend-client`: пока заготовка, поэтому формат публичной ссылки явно
  помечен как тестовый, а не выдан за production URL.

## 3. Что реализовано

### Каркас и инфраструктура

- Vite + React 18 + TypeScript + Tailwind.
- dev-сервер на `3001`, proxy `/api` и `/uploads` на `localhost:8000`.
- Конфигурация `vitest`, `tsconfig`, PostCSS, Tailwind.
- `.env.example` с `VITE_API_URL` и `VITE_PUBLIC_MAP_BASE_URL`.
- `package-lock.json` для воспроизводимой установки.

### Модель данных

- Локальные типы в `src/types/venue.ts` расширяют контракт только опциональными
  полями. `shared/types.ts` не изменялся.
- Добавлены:
  - `Wall`, `Room`, `AssetReference`;
  - `planAsset` у этажа;
  - `panoramaId` и настройки типов у POI;
  - `schemaVersion`, `publicUrl` у площадки;
  - категории `panorama`, `info`, `wardrobe`, `other`.
- Нормализация и миграция JSON: неизвестные категории превращаются в `other`
  с сохранением исходного значения, отсутствующие поля заполняются безопасно.
- Реестр типов POI (`src/config/pointTypes.ts`) отделён от холста.

### Редактор

- Создание проекта, демо-карта с двумя этажами и открытие опубликованных карт с backend.
- Управление этажами: заметная лента этажей, добавление, удаление, переключение, название, уровень.
- Загрузка плана через drag-and-drop, подтверждение замены при наличии объектов.
- Холст React-Konva:
  - zoom/pan, вписывание плана, сетка при отсутствии изображения;
  - перетаскивание точек, панорам, концов стен и лестниц;
  - инструмент «Стена» с цепочкой сегментов и длиной в метрах;
  - инструмент «Лестница»: марш с шириной, направлением и связью между этажами;
  - инструмент «Помещение» с площадью;
  - калибровка масштаба по известному отрезку;
  - горячие клавиши и подсветка выбранного объекта.
- Свойства: проект, этаж, точка, стена, лестница, помещение, панорама.
- Связывание лестниц между этажами, переход к парной лестнице и очистка связей
  при удалении лестницы или этажа.
- Специализированные настройки POI: Wi-Fi, вход/выход, гардероб, информация,
  «другое» с произвольными полями.
- Панорамы: загрузка, превью, привязка к POI, список панорам без точки.
- Undo/redo на основе истории Zustand; drag объединён в одну транзакцию.
- Автосохранение черновика в `localStorage` и предупреждение при уходе со страницы.

### Файлы и публикация

- Локальные планы и панорамы хранятся в IndexedDB (`ttk-admin-assets`).
- В итоговые данные попадают метаданные и `local-asset://<id>`, а не бинарные данные.
- `publishVenue`:
  1. находит локальные ассеты;
  2. загружает их через `POST /api/upload`;
  3. заменяет URL на server-side;
  4. формирует полные данные карты и сохраняет их через `PUT /api/venues/{slug}`.
- Открытие опубликованных карт через `GET /api/venues` в модалке «Открыть карту с сервера».
- В интерфейсе нет импорта или экспорта JSON-файлов.
- QR публичной ссылки, скачивание PNG, копирование ссылки.
- Если backend не вернул `publicUrl`, показывается тестовый адрес
  `VITE_PUBLIC_MAP_BASE_URL/m/<slug>` с явным предупреждением.

## 4. Проверки

Окружение: Linux, Node.js `v22.23.4` (портативная установка в `~/.local/node22`),
Docker в окружении недоступен.

| Проверка | Результат |
| --- | --- |
| `npm run typecheck` | успешно |
| `npm run test` | 13/13 passed |
| `npm run build` | успешно, `dist/` собран |
| `npm run dev` на `:3001` | HTTP 200 |
| Playwright smoke (Chromium) | успешно |
| Публикация через stub backend | успешно |

Smoke-тест в реальном браузере проверил:

- стартовый экран и открытие демо-карты;
- загрузку плана и подтверждение замены;
- добавление точки и undo;
- рисование стены и цепочки стен;
- добавление третьего этажа и переключение обратно;
- создание лестницы и связывание этажей;
- замену панорамы и её привязку к точке;
- QR-модалку и скачивание PNG;
- сохранение черновика после перезагрузки;
- открытие опубликованной карты с backend.

Публикация проверена с локальным stub-backend, повторяющим контракт реального
API: health, upload, PUT. Подтверждено, что два локальных файла были загружены,
`local-asset://` заменён на `/uploads/...`, а в данных сохранены стены, помещения и лестницы.
Проверка с реальным FastAPI не выполнялась, так как Docker в окружении недоступен.

Во время smoke-теста найден и исправлен реальный runtime-баг: Konva падал при
первом рендере, пока контейнер имел нулевой размер. Холст теперь рендерится
только после измерения контейнера.

## 5. Ограничения

- Backend хранит данные in-memory; после рестарта публикацию нужно повторять.
- Backend MVP строит маршрут только по первому этажу.
- Авторизации нет; редактор не расширяет API и не добавляет защиту.
- `local-asset://` действителен только в браузере, где был загружен файл.
  Для переноса карты используйте публикацию на backend.
- Публичный URL по умолчанию тестовый, пока backend не начнёт возвращать
  `venue.publicUrl` или не будет настроен `VITE_PUBLIC_MAP_BASE_URL`.
- Production-бандл содержит Konva и React-Konva; Vite предупреждает о размере
  чанка (~657 kB). Для хакатона это приемлемо, оптимизация не входила в задачу.

## 6. Изменения вне frontend-admin

Нет. `shared/*`, `backend/*`, `frontend-client/*` и корневые файлы не изменялись.
Портативный Node.js установлен только в домашнем окружении разработчика
(`~/.local/node22`) и не является частью репозитория.

## 7. Как закоммитить

Из корня репозитория:

```bash
git status
git add frontend-admin/
git commit -m "feat(frontend-admin): интерактивный редактор карт павильонов"
git push -u origin youngire-frontend-admin
```

Проверить, что в коммит не попали `node_modules/`, `dist/`, `.env.local`:

```bash
git status --short
git diff --cached --name-only | grep -v '^frontend-admin/' || true
```

## 8. Как проверить вручную

1. `cd frontend-admin && npm install && npm run dev`.
2. Открыть http://localhost:3001.
3. Нажать «Открыть демо-карту».
4. Выбрать тип точки, кликнуть по плану, перетащить точку, нажать `Ctrl+Z`.
5. Нарисовать цепочку стен, завершить `Enter`, изменить масштаб через «Масштаб».
6. Добавить этаж, загрузить план, заменить панораму у точки, создать лестницу.
7. Открыть «Опубликовать», проверить QR и скачать PNG.
8. Создать лестницу, связать её с лестницей на другом этаже и проверить переход.
9. Перезагрузить страницу и убедиться, что черновик восстановился.
10. При запущенном backend нажать «Опубликовать на backend» и проверить
    `GET /api/public/{slug}`: в данных должны быть стены, помещения и лестницы.
