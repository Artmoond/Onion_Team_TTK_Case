# Студия организатора — редактор карт павильонов

Десктопный редактор интерактивных карт для проекта «Карта пространства ТТК».
Позволяет загрузить план этажа, разметить стены, помещения и лестницы, расставить
POI, привязать 360° панорамы, проверить карту в локальном режиме и опубликовать
площадку через существующий backend API. Пользователь работает только с картой:
данные для backend формируются и отправляются автоматически при публикации.

## Стек

- React 18 + TypeScript + Vite
- Tailwind CSS
- React-Konva / Konva
- Zustand (история изменений, undo/redo)
- react-dropzone (планы и панорамы)
- qrcode.react (QR публичной ссылки)
- Vitest

## Быстрый старт

Из корня репозитория (поднимает backend и все фронтенды):

```bash
docker compose up --build -d
```

Редактор: http://localhost:3001

Локально без Docker:

```bash
cd frontend-admin
npm install
npm run dev
```

Требуется Node.js 18+ (рекомендуется 20 или 22).

## Переменные окружения

Скопируйте `.env.example` в `.env.local` при необходимости:

```bash
cp .env.example .env.local
```

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `VITE_API_URL` | `http://localhost:8000` | Backend API |
| `VITE_PUBLIC_MAP_BASE_URL` | `http://localhost:3000` | База тестовой ссылки `/m/<slug>` |

В Docker Compose `VITE_API_URL` уже передаётся в контейнер.

## Что умеет редактор

- Создание проекта с нуля, демо-карта «Инновационный Экспоцентр ТТК» и открытие
  опубликованных карт с backend.
- Несколько этажей: заметная лента этажей под шапкой, быстрое переключение,
  добавление, удаление, название и уровень.
- Загрузка плана (JPEG/PNG/WebP/SVG) с перетаскиванием и подтверждением замены.
- Инструменты: выбор, панорамирование, стена, лестница, помещение, калибровка масштаба.
- Стены рисуются цепочкой: после каждого сегмента следующая стена начинается
  от последней точки; `Enter` или двойной клик завершают цепочку.
- Лестницы как объекты-марши: длина, ширина, направление, связь с лестницей
  на другом этаже, переход к парной лестнице.
- POI с расширенными типами: стенд, зал, еда, санузел, сервис, Wi-Fi, вход,
  панорама, информация, гардероб, другое; настройки Wi-Fi/входа/гардероба.
- 360° панорамы: загрузка файла, привязка к точке, превью, список.
- Стены с длиной в метрах, помещения с площадью и лестницы с размерами;
  пересчёт при смене масштаба.
- Undo/redo, транзакции при перетаскивании, горячие клавиши.
- Локальный черновик в `localStorage`, локальные файлы в IndexedDB.
- QR-код публичной ссылки и скачивание PNG.
- Публикация: редактор сам формирует данные карты, загружает локальные файлы
  через `POST /api/upload` и отправляет их через `PUT /api/venues/{slug}`.
- В интерфейсе нет импорта или экспорта JSON-файлов.

## Горячие клавиши

| Клавиши | Действие |
| --- | --- |
| `Ctrl/Cmd+Z` | Отменить |
| `Ctrl/Cmd+Shift+Z`, `Ctrl/Cmd+Y` | Повторить |
| `Delete`, `Backspace` | Удалить выбранный объект |
| `Esc` | Сбросить текущий инструмент |
| `Enter` | Завершить цепочку стен или помещение |
| `Space` + перетаскивание | Временно панорамировать холст |
| Колесо мыши | Масштаб холста |

## Локальный режим и публикация

Backend может быть недоступен: редактор продолжает работать локально.
План и панорамы сохраняются в IndexedDB браузера, черновик — в `localStorage`.
В этом режиме ссылки `local-asset://...` действительны только в текущем браузере.

При публикации редактор:

1. Находит все локальные ассеты (`planAsset`, `panorama.asset`).
2. Загружает их через `POST /api/upload`.
3. Заменяет `local-asset://` на URL, полученный от backend.
4. Формирует итоговые данные карты, включая стены, помещения и лестницы.
5. Отправляет их через `PUT /api/venues/{slug}`.

Пользователю не нужно выбирать или сохранять JSON-файлы. Загрузить ранее
опубликованную карту можно кнопкой «С сервера» (`GET /api/venues`).

Если backend не возвращает `publicUrl`, QR ведёт на тестовый адрес
`VITE_PUBLIC_MAP_BASE_URL/m/<slug>`; в интерфейсе это явно помечено.

## Ограничения

- Backend хранит площадки in-memory: после перезапуска контейнера публикацию
  нужно выполнить повторно. Загруженные файлы остаются в `data/uploads`.
- Backend MVP строит маршрут только по первому этажу.
- Авторизации в backend пока нет; редактор не добавляет собственных endpoint.
- `local-asset://` нельзя переносить между браузерами. Для передачи карты
  используйте публикацию на backend.
- Лестницы связывают этажи на уровне данных карты, но backend MVP пока строит
  маршруты только по первому этажу.
